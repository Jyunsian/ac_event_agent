- 每個 frozen candidate 都產出 triggered／untriggered／unknown、D2／D3／D7 收益拆解、1,000 次 user bootstrap、單尾 Welch 與完整家族 Holm 結果。
- `build_casual_targets` 對 `revenue_timing=available_at` 的延遲／未到資料傳播 null，不把未取得收益補零或提前用於 exploration D7。

## Criteria

### C1 — 完整家族推論

- `family_size == len(results)`，結果順序與 freeze `candidate_ids` 完全相同；任何 candidate 缺列時 Holm 拒絕 incomplete family。
- Welch 為 one-sided greater；不可檢驗的少樣本、未知收益或零變異保留，使用 `p_value=1` 進入 Holm。
- Holm 只在所有 candidate batch 齊全後執行，最後 manifest 明寫 `family_correction_complete=true`。
- 無訊號與 2,000 family 的情境不產生假通過；少數強訊號、重尾與退化樣本都有獨立測試。

### C2 — D2／D3／D7 與時間邊界

- D2 固定 `[0,48)`＋`[48,168)`；D3 固定 `[0,72)`＋`[72,168)`；D7 為 `[0,168)`。
- 每一個可觀察用戶與每一 group 先驗證 `early + remaining == D7`，再發布 revenue、ARPU 與 difference。
- triggered／untriggered／unknown 分開計數；任一 group 有未知收益時該 group 的 revenue／ARPU 保留 null。
- `decision_time_hours > checkpoint` 時輸出 `LATE_INDICATOR_NOT_DECIDABLE`，不使用後來 membership 倒推早期比較。
- `available_at` 晚於資料完整截止的 D7 收益為 null；72h 後才取得的收益不能回填早期 membership。

### C3 — 診斷與恢復

- install day／acquisition source 僅標 `diagnostic_only`；cell 任一組少於 20 或含未知收益，difference 隱藏但分母保留。
- Holdout validation 不修改 threshold、quota、priority、candidate order 或 frozen bytes。
- 人工在 durable batch 後中斷，目錄不出現最終 manifest；同 family 可恢復，結果與無中斷版本 byte-identical。
- 錯誤 candidate identity 的 batch 被拒絕；V2／V3 batch version 產生不同 cache identity。既有真 PG/S3 batch、重領、checkpoint 與 fence 回歸保持通過。
