## 交付

- `casual_search.py` 只接受 `kind=exploration` 且與 targets manifest／split／source hash 一致的 V3 features；門檻只從成熟 exploration 正值分布產生。
- 候選涵蓋 IAA、Session／Retention、Level Progress、Level Friction、預註冊 Sequence 與受控 Cross-category；Cross 每個 Category × observation end 最多 20 個父條件、兩個原子且不允許巢狀。
- `memberships.parquet` 保存每個 Discovery candidate 的 triggered／untriggered／unknown membership；manifest 保存 membership SHA-256、探索統計與單一主要排除原因。
- `casual_selection.py` 依 Category Pareto layer、membership diversity、固定 Validation 配額與逐輪回補選出 family；優先名單最多 10 且先嘗試覆蓋不同 Category。
- `casual_freeze.py` 在讀取 holdout 前保存候選精確順序、family size、priority order、policy／feature／split／search／selection／membership hash 及後續全家族驗證規則。
- `pipeline.build_v3_discovery_stages` 將 exploration features → discovery → selection → freeze 固定為單一 pre-holdout 邊界；正式可恢復 StageRunner／PG/S3 串接在 CG04–CG06 隨完整 validation/report 一起發布，避免半套 baseline。

## Criteria

### C1 — 有限生成與預算

- 固定 observation end、threshold grid、方向、minimum denominator、sequence gap/repeats 由 V3 contract／policy 控制；非法 config 由 V3 schema 拒絕。
- 小型壓力案例建立六類各 5,000 筆候選，實際呼叫同一 allocator：Discovery 恰為 20,000、Validation 恰為 2,000。
- Discovery 實際初始分配：IAA 3,500、Session 3,000、Progress 4,500、Friction 3,000、Cross 4,000、Sequence 2,000。
- Validation 實際初始分配：350、300、450、300、400、200；不足時按固定 Category 順序逐輪回補。
- 每個生成但未留在下一層的候選均保存 canonical、exact membership、sample、near duplicate、cross sample 或 category budget 原因。

### C2 — 去重、篩選與多樣性

- Canonical AST identity 先去重；membership hash 同時包含 triggered／untriggered／unknown，避免只比較 hit set 而誤合併不同可判定母體。
- Exact membership 依語意複雜度、P90、candidate ID 固定代表；Cross 生成後再次與既有原子及 Cross 做 exact membership 去重。
- 手算 near-duplicate 邊界：995/1000 Jaccard = 0.995、coverage delta = 0.005 時判定重複；994/1000 不判定。
- ratio／平均／duration 逐用戶檢查 minimum denominator；兩組未達 `min_group_users` 不占 Validation。
- Pareto 維度固定為 exploration D7 ARPU difference、coverage、負 P90；同 layer 以與已選集合最大 Jaccard 較低者優先。
- 同一封存 feature/target/config 重跑，`manifest.json` 與 `memberships.parquet` bytes 完全相同。

### C3 — Holdout 前凍結

- Freeze receipt 保存 `candidate_ids` 精確順序、`family_size`、`priority_ids`、`policy_identity`、`feature_id`、`split_id`、exploration scope 及所有直接上游 hash。
- 測試在 freeze 後新增／改動 holdout-only 檔案，再由同一 selection 產生另一份 receipt，兩份 `frozen.json` bytes 完全相同。
- Freeze 規則固定 bootstrap=1,000、one-sided Welch、完整 frozen family Holm、不可檢驗 p=1；CG04 只能填證據，不能補選或重排。
