## 已固定的語意

- 比較點 24/48/72/96/120/144h；D7 為 [install,install+168h)。
- 累積規則身分不含截止時間；固定時點條件呈現進入/退出，不能宣稱累積。
- 每位用戶每個規則記錄首次達標；未知不當未達標。首次時間使用實際可用時間，不回填延遲收入。
- 滾動窗口採 [t-24h,t)，24h 後開始。當事件到達時計算包含該批事件的右極限；事件正好在報告截止時間時不納入該比較點。此差異須有邊界測試。
- 滾動僅含廣告次數/收益、Session、關卡開始/完成/失敗次數；不含滾動交叉/序列/比率。
- 每天新增使用首次達標時間區間 [0,24)、[24,48)…；24h 的定時判斷屬於 24h 比較點，其端點事件仍排除。
- 收入對照按探索集最接近覆蓋率選取，平手按固定規則 ID；報告顯示實際差距。所有條件、配對、正式比較單位與優先名單在讀取 holdout 前凍結。
- 20k 基本規則；2k 正式比較單位。每規則/時點/問題計一單位；完整時間組合不拆分。少量優先規則最多十個。
- 全量描述與 holdout 證據分開；1,000 bootstrap；所有正式聲明一起 Holm；樣本門檻預設各組 100。
- 不選唯一最佳截止，不把新增辨識收益稱為因果增量。客戶文字使用具體時間與「多找到哪些玩家」。
- V3 CG06 保持 closed_partial。本版測試不能冒充投放實驗。

## 實作補充

- 滾動收入以廣告「發生時間」決定是否仍在 24h 範圍內，以「可取得時間」決定能否用來判斷。兩者皆需符合；過期廣告的延遲收益不能變成新行為。
- 優先比較保留不同類別，避免六個時間點都指向完全相同人群的重複方案。它只是展示清單，不代表不同期限的總冠軍。
- 完整探索結果獨立下載為 `discovery`，不塞入主報告或 Agent 回應。Agent 取得有界聚合欄位，報告細節保留原始聚合證據。
- 組合父條件仍限制每類別／時間點最多 20 個，優先保留有辨識人群與不同人群的條件；跨時間平衡父條件重用，避免六個時間點反覆搜尋相同少數組合。只使用探索資料，父條件 ID 寫入搜尋紀錄。
