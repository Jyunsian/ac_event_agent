# Agent 對話 UX Review

日期：2026-09-11

## Review 結論

原本畫面把使用者訊息、工具紀錄、完成狀態、報告 context 都當成同一層內容，造成分隔線太多、重複狀態太多，真正的回答反而不突出。輸入框也像表單，不像持續對話的操作入口。

## 對標後的共同原則

- Gemini Canvas：輸入框是主要控制入口，大型結果在旁邊區域呈現，並支援針對選中內容繼續詢問。
- Claude Artifacts：對話與可編輯產物分開，使用者可在同一對話中針對產物繼續修改。
- Codex：保留 thread、顯示必要進度，完成後讓使用者查看結果，而不是把每個系統事件都當作主要訊息。

## 已採用的設計決策

1. 對話是主體：使用者訊息以輕量氣泡呈現，助理回答使用乾淨文字排版，不再每段都加框線。
2. 工具過程預設收合：只顯示「分析過程、步驟數、目前狀態」，需要時再展開；工具 ID 與重試次數不直接暴露。
3. 狀態不重複：工具完成後不再另外顯示一行「已完成」；失敗、取消與進行中才保留操作提示。
4. Context 靠近操作：目前報告版本與是否已選事件放在輸入框內，也保留在使用者訊息下方，避免送出時不知道 Agent 在看什麼。
5. 輸入框改成 Agent composer：固定在底部、內容自動增高、Enter 送出、送出按鈕有明確可用狀態。
6. 空白狀態只保留一句承諾與三個可直接使用的問題，不再先塞入大段產品說明。
7. 桌面與窄螢幕共用相同資訊層級；窄螢幕只縮減次要快捷鍵，不改變操作方式。
8. 事件詳情只遮罩右側結果區；使用者選中事件後，仍可直接操作左側 Agent，邊看證據邊提問。

## 保留的產品邊界

- 報告與圖表仍留在右側結果區，不把大型資料表塞回聊天流。
- Agent 只取得當前 run、報告版本、所選事件與工具回傳的必要聚合證據；原始資料不直接放進聊天訊息。
- 引用仍可跳回右側的對應報告證據。
