# V4 交付與使用方式

V4 的重點是把「什麼行為值得比較」與「需要等多久」放在一起看。它保留七天累積廣告收入作為目標，不自動替客戶決定唯一回傳期限。

2026-09-17：V4-01 至 V4-06 的本地交付門檻已通過。126 項相關 Python 測試、21 項前端模型測試、25 項 Agent 測試與建置通過。10 萬事件／2 萬規則／2,000 正式比較的一般分布約 194 秒，集中分布約 159 秒，均在原定限制內。這些是合成資料的工程驗收。

可查看本地實際計算示範：[`一般分布離線報告`](../.runtime/v4-capacity-07/report_html.html)，以及 [`集中分布离線報告`](../.runtime/v4-capacity-concentrated-02/report_html.html)。不是預填的示意數字。

## 怎麼使用

1. 上傳事件與用戶資料，確認安裝起點、欄位和資料完整截止時間。首次分析使用 V4；有既有固定門檻時，可以一併輸入名稱、條件和截止時間。
2. 右側報告先說明資料能分析哪些方向，再列出少數值得比較的行為。
3. 打開一條規則，看安裝後 24、48、72、96、120、144 小時的結果。累積型條件會分開顯示每天第一次達標的人，指定時間判斷的條件則顯示符合、加入與退出。
4. 選同一個時間點，與單純累積廣告收入門檻比較。連續 24 小時的條件另外顯示同門檻的累積人群，幫助理解集中遊玩與慢慢累積的差別。
5. 切換「本批觀察」與「另一批用戶的結果」。人數不足仍顯示可計算的結果，但不宣稱方案通過。

Web、CSV、JSON、離線 HTML 和 Agent 聚合讀取共用計算結果。完整搜尋結果另行下載，主報告只保留有界摘要，單條規則的完整證據按需讀取。

## 這次驗收什麼

- 計算正確：首次達標、每天新增不重複、收益對帳、缺資料與零收入分開、延遲收入不提前使用、窗口邊界正確。
- 比較公平：條件、收入對照與展示名單先用探索資料固定，再讀另一批用戶；六個時間點分別計算正式比較數量。
- 流程完整：上傳、持久任務、Python Worker、報告 API、下載、Agent 聚合讀取，以及中斷後恢復。
- 保留舊版：V4 使用獨立產物與快取，不改寫舊報告，也不重置已揭露資料的驗證資格。
- 使用順暢：桌面、手機、每日表格、時間切換、另一批用戶切換與離線報告。
- 容量：10 萬筆事件、2 萬基本規則、2,000 正式比較；保留 1,000 次重抽樣與既有資源限制，另測事件集中在少數玩家的情況。

實際完成狀態以 `../PHASE_STATUS.md` 與 `../evidence/V4-06.md` 為準。

## 邊界

本次證據使用合成資料與本地 PostgreSQL／S3／Worker；不代表客戶資料上的效果或投放提升。沒有新增 ML、ROI、線上回傳或雲端部署。

V4 支援本批資料內固定方案後的另一批用戶驗證。舊平台的任意分群分支工具及跨資料集儲存方案重驗尚未移植到 V4，入口會明示不支援；不把它們當成已完成能力。

非收益行為依匯入事件時間判斷，無法推測來源未提供的額外傳輸延遲。收入則依資料所定義的可取得時間判斷；不能可靠還原的首次時間保持未知。
