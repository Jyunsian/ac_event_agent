# Candidate Event V2 — 已批准的實作計畫

狀態：使用者已批准，V2 實作與驗收進行中。實際階段以 PHASE_STATUS.md 為準；不改寫 PH01–PH42 或 L01–L05 的歷史證據。逐條追蹤見 docs/CANDIDATE_V2_ACCEPTANCE.md。

## 1. 目標與範圍

讓內部分析人員與客戶看懂候選的 D7 收益辨識、覆蓋與實際觸發速度，取得少數具不同優勢的優先比較，以及本次搜尋內全部實際評估結果。

- 沿用用戶表與事件級 CSV，每次 ad_impression 記錄該次展示收益；不新增必要輸入欄位，不要求用戶級或 Campaign 成本。
- 純 IAA：廣告次數、累積收入、Session、有效時間、有限 AND／OR／兩步序列。不擴充任意 App 產品事件。
- 所有 acquisition source 合併為主要母體；沿用成熟用戶按安裝日期約 70/30 探索／驗證切分，來源差異僅輔助診斷。
- 完整 D7 [0,168h) 收益為主目標，剩餘收益不是淘汰條件，不跨不同剩餘時長排名。
- 窗口固定於批次安裝／首次開啟起點；首次達標回傳一次。滾動窗口只記於 AGENTS.md 待辦，本輪不實作。
- 維持左對話右報告；首報告不依賴 LLM。不包含雲端部署、SDK／平台回傳、ROI 保證或投放自動化。

## 2. 搜尋與優先比較

### 窗口、門檻與預算

- 預設窗口 1、3、6、12、24、48、72、96、120、144 小時；168h 另列邊界診斷，不進優先名單。窗口 [起點,起點+W)。
- 每個窗口／格式的探索集正值分布取 5%、10% 至 95% 分位數，與既有固定網格聯集。次數向上取整；有效時長向上至秒；去除零值與重複門檻。
- 累積廣告收入另加探索集正值最小至最大範圍內的 1、2、5 × 10^n 美元刻度；依全部廣告及各已觀測廣告格式搜尋。保存原始精確門檻，展示格式不得回寫運算。
- 相同窗口最多兩個原子 AND／OR；每個窗口分別選最多 20 個探索集父條件，依下述多維排序。序列保留既有事件類型、60/600/3600 秒間隔與 1/2/3 次不重疊模板。
- 每次最多實際評估 2,000 候選；原子／組合／序列預算 50%/30%/20%。不足額按原子→組合→序列回補，類型內輪流分配窗口；固定 seed／candidate ID 決定平手。
- 邏輯等價合併，僅觀測人群相似仍保留。保存生成、合併、評估、預算排除數及逐條原因。未評估不冒充樣本不足或不支持。

### 優先比較

- 探索集兩組均達既有 min_group_users 且 D7 平均收益差為正，才進優先比較池；其他實際評估條件仍交付。
- 以收益差額、覆蓋率越高及觸發 P90 越低建立 Pareto 分層。支配需全部不劣且至少一項嚴格較好。
- 每層輪流由收益差降序、覆蓋降序、P90 升序選取；同值優先原子、兩原子組合、序列，最後以 ID 決定。最多 10 個，不湊數。
- 與已選候選探索集 Jaccard ≥ 90% 者列相似替代，不占優先名额，完整清單保留。保存最相似優先候選及比率。
- 優先名單／順序在看 holdout 前固定；驗證失敗照列，不依 holdout 補選。角色用「價值差較大／覆蓋較廣／達標較快」，不產生綜合總分或自動投放保證。

## 3. 整批驗證與診斷

- 分離全部待驗證候選（最多 2,000）與優先 ID（最多 10）；凍結候選、規則、名單、診斷窗口及統計家族，再讀 holdout。
- 全部候選取得 holdout 人數、ARPU、差額／比率、覆蓋、P50/P90、逐日結果與狀態；無觸發、无對照、缺失或樣本不足保留原因，不消失。
- 新增單尾 Welch 檢驗（觸發者 D7 平均收益較高）與 Holm 全家族校正，alpha=0.05。不可檢驗者 p=1 仍留在凍結家族。零變異或非有限結果明示不足，不轉成通過。
- 保留既有樣本、品質、每日方向及 bootstrap 區間下界 gate，不降低條件。固定 seed、1,000 次 user-level bootstrap 95% 描述區間，與 Holm 通過狀態分開顯示。
- SciPy 作鎖版新增依賴；Holm 排序、逐步調整與單調化以固定參考驗證。記錄重尾分布／Welch 近似限制，不稱因果驗證。參考 https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.ttest_ind.html 與 https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html 。
- 每候選按其 W 固定分組，計算 [0,W)、[W,168h)、完整 D7 的兩組人數／收益／差額；前後相加必須等於 D7。比率明示未觸發者分母，分母零則不可計算，不用比率跨窗口排名。
- 優先候選另做共同 24/72/144h landmark，只以該時刻前是否已首次觸發分組，同一剩餘期間比較。D6 不因剩餘短而失敗；168h 顯示無剩餘期間；個別觸發後收益沿用排除同時間事件規則，不能混稱共同 landmark。
- 每個成熟安裝日列觸發數／覆蓋，補齊期間零值日期；無安裝用戶日期覆蓋為未知，不是零。標安裝批次觀測量，不宣稱平台接收量或足夠學習。
- 全候選提供 source 內兩組收益方向；unknown 獨立列，任一組少於 20 人隱藏收益比较並註不足。來源診斷不改全量排名或獨立證據，不宣稱已排除混雜。
- 收益時間沿用 immediate/available_at/unknown。unknown 可另外按 event_time 計算假設性累積收入條件，但須獨立標示時間假設與工程待確認，不能以它升級為當時可執行的已驗證事件；不新增必填欄位。
- 全部 holdout 揭露仍登記；調條件 followup 為探索，不因擴大清單洗掉污染。新批次舊 finding 重驗固定舊條件。

## 4. 呈現與接口

- 右側候選頁分「優先比較」「全部結果」「搜尋範圍與紀錄」，保留原雙欄布局。
- 主表列完整起點／條件、兩組樣本、覆蓋、符合／未符合 D7 ARPU 與差額、P50/P90、證據與比較角色。明寫「首次開啟後前 6 小時」，不模糊成任意 6 小時。
- 全部結果每頁 50 筆，按窗口、類型、格式、證據、角色篩選及按差額／覆蓋／速度排序；保留不足、不支持、相似及假設性條件。
- 所有已評估候選共用證據卡：定義；覆蓋與速度；D7 三組收益、差額與區間；窗口前後收益；探索／驗證對照、逐日及 Holm；來源診斷；相似候選；工程規格／來源。
- 主要內容用白話、表格與圖，原始 JSON 折疊。累積收入門檻图按同窗口／格式展示覆蓋與 D7 差額兩張對齊圖，點擊能定位候選。
- UI、HTML、CSV、JSON 均從相同 Python 產物渲染。離線 HTML 包含全部已評估候選及證據，可本地搜尋／分頁，不依賴 API 或外部資源。完整匯出與篩選匯出分開；後者附條件與總數。
- 報告 v2 保留 candidates 為最多 10 個優先項，完整清單及搜尋紀錄另作版本化產物。新增 run/report version/candidate ID 定位的分頁清單與詳情 API，不一次載入全部證據。
- Agent 摘要預設僅優先項；增加候選搜尋／分頁工具，一次最多比較 10 個。新引用維持 scope/hash/揭露檢查。禁止把數千候選直接送入模型。
- 舊版報告保持可讀，新欄位缺失標「此版本未計算」，不得補造；原報告 bytes/hash 不變。更新 calculation version/cache identity，禁止沿用舊搜尋／選擇／驗證產物。
- 分批計算、持久 checkpoint 與可恢復讀回；整批校正完成前不發布部分「驗證通過」。

## 5. 分階段執行與驗收

每階段開始前閱讀 PHASE_STATUS 及前階段證據；沿用共同 G1–G5。為 V2 建立 CV01–CV05 狀態與 evidence/CVxx.md，逐階段 criteria 通過後繼續，不改寫歷史 Gate。

### CV01 合約與真值
- C1：同步 PRD/TECH_PLAN，固定 v2 合約、預算、統計與時間語意，已確認與方法假設分開。
- C2：建立可手算 fixtures，含新窗口、收益門檻、晚期觸發、重尾與來源差異；來源不覆寫。
- C3：v1/v2 讀取及 schema 負例通過，建立可逐條驗收的追蹤清單。

### CV02 搜尋與選擇
- C1：各窗口／類型／收入網格產生真候選，預算與剪枝紀錄一致。
- C2：Pareto 與重疊替代符合上述規則，保留高覆蓋／高價值／快速取捨，確定性可重現。
- C3：變更 holdout 不影響生成、凍結前名單或搜尋紀錄；窗口與首次觸發回歸通過。

### CV03 整批驗證
- C1：全部實際評估候選凍結後有結果，Holm 手算、無訊號／少數真訊號／重尾／退化樣本測試通過。
- C2：收益分解加總、D6/168h、source 小樣本、零事件／未成熟／未知收入時間測試通過。
- C3：真 PG/S3/checkpoint 恢復及驗證揭露回歸通過，未校正完成不發布通過；核心失敗不得外部延期。

### CV04 呈現與交付
- C1：UI/HTML/CSV/JSON 清單筆數、所有狀態、主要數字與候選 ID 一致，詳細卡真實引用產物。
- C2：桌面與手機目視驗收；離線 HTML 關 API 可用；篩選／排序／切頁不觸發新計算，缺值不補零。
- C3：Agent 搜尋/比較引用範圍正確，舊報告可讀且父版 hash 不變；合成 mockup 數字不得流入實際報告。

### CV05 整合與容量
- C1：上傳→Python 首報告→完整清單/卡→對話/分支→匯出端到端與相關既有回歸通過。
- C2：新版 10萬/100萬事件、最多 2,000 候選實跑，記時間/RSS/磁碟/產物大小/獨立真值；至少有一組實際達 2,000，不能拿縮小候選數冒充上限驗收。
- C3：沿用現有資源限制，若超限修復並重驗，不偷降候選或抬配額；保留失敗證據。更新容量、外部清單與交付結論。

## 6. 完成與停止條件

CV01–CV05 所有 C1–C3/G1–G5 有實際命令、退出碼與產物並 passed，才宣告完成。缺真客戶資料、真模型授權或雲端可沿既有外部延期規則留檔，不冒充外部通過；整批運算或容量失敗不能列外部延期。需求數據不支持候選時，成功交付可為零推薦，不能為湊數降低判定。完成本地交付後停止，滾動窗口與部署等待另一範圍授權。
